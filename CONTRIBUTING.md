# Contributing to Pulse

## Development Rules

1. Never push directly to main.
2. Create a feature branch for each task.
3. Follow the project's coding standards.
4. Test your changes before creating a PR.
5. Include a clear description in every PR.
6. Resolve merge conflicts before requesting review.
7. Never commit API keys or environment files.

## Branch Naming

feature/feature-name
fix/bug-name
docs/documentation-name

## Commit Naming

feat:
fix:
docs:
style:
refactor:
test:
chore:

## Pull Request Process

1. Push your feature branch.
2. Create a PR targeting develop.
3. Describe the implementation.
4. Add testing steps.
5. Request review.
6. Merge after approval.
